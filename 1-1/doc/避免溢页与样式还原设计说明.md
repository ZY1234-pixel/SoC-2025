# 避免溢页与样式还原设计说明

## 1. 问题背景

在将图片型文档还原为 DOCX 时，一个常见问题是：

- 希望尽可能还原原始文档的 **字号、行距、页边距、缩进、表格宽度、图片尺寸** 等样式。
- 同时又希望导出的 Word **不要因为内容稍有偏差而溢出一整页**，导致分页错乱、表格超宽、图片挤占文本等问题。

很多实现会引入一个“整体缩放”逻辑：

- 当发现页面内容超出目标页时，就统一缩小字号、行距、块尺寸或整页比例。

这种做法虽然可以快速避免溢页，但也会引入一个严重问题：

> 如果把“为了防溢页而做的缩放”反过来当作“真实样式”写回系统，那么字号、行距、页边距等推断结果会被系统性污染。

因此，必须把：

- **样式还原**
- **版面拟合**

拆成两条不同的逻辑链路。

---

## 2. 核心原则

### 2.1 不要把缩放后的值当作真实样式

整体缩放本质上是渲染阶段的修正，而不是原始文档的真实排版属性。

例如：

- 原始推断字号为 `10.5pt`
- 因页面溢出，对整页应用 `0.97` 的缩放
- 最终渲染字号临时变为 `10.185pt`

这并不意味着原文真实字号就是 `10.185pt`。真实样式仍应保留为 `10.5pt`。

### 2.2 样式还原和版面拟合必须分层

建议把系统中的样式信息分成两层：

- **style_inferred**：表示根据源图像或源页面坐标系推断出来的真实样式
- **render_fit**：表示为了当前导出不溢页，对样式做的局部或整体修正

示例：

```json
{
  "style_inferred": {
    "font_size_pt": 10.5,
    "line_spacing_mode": "multiple",
    "line_spacing_value": 1.5,
    "space_before_pt": 0,
    "space_after_pt": 6,
    "page_margin": {"top": 72, "bottom": 72, "left": 90, "right": 90}
  },
  "render_fit": {
    "page_scale": 0.985,
    "font_delta_pt": -0.25,
    "line_spacing_delta": -0.05,
    "space_after_delta_pt": -1
  }
}
```

### 2.3 先还原样式，再做排版模拟，再做最小破坏修正

合理顺序应为：

1. 在源页面坐标系中推断真实样式
2. 在目标 DOCX 容器中忠实渲染
3. 检测是否溢页、超宽、分页异常
4. 仅对有问题的区域做“最小破坏”的修正

而不是一开始就整体缩放整页。

---

## 3. 为什么整体缩放会导致字号推断错误

### 3.1 字号、行距、边距属于不同量纲的样式属性

在 Word / OOXML 中：

- 字号通常用半点值表示，例如 `10.5pt`
- 行距可以是固定长度，也可以是倍数行距
- 段前段后是长度值
- 页边距属于 section 级别属性

这些量都应该单独推断，而不是统一乘一个比例后直接写回样式层。

### 3.2 缩放后的测量值已经不是原始样式

如果你是在“缩放后的目标布局”中再去反推字号、段落间距、图片尺寸，那么所有值都会受到整体缩放影响。

这会产生两个后果：

1. **样式漂移**：每一次导出都可能越来越小
2. **不可追溯**：系统无法再区分“原文样式”和“渲染修正”

### 3.3 后续迭代会越来越难

如果样式和拟合混在一起，后面会很难处理：

- 同一份 IR 多次导出
- 切换不同页面尺寸
- 支持 HTML/Markdown 等其他输出格式
- 在编辑器中做人工修订后回写

---

## 4. 如何尽可能准确地还原字号、行距、页边距

## 4.1 字号推断

### 4.1.1 不要从最终渲染结果反推字号

字号应在**源页面坐标系**中推断，而不是在已经缩放后的渲染页面中推断。

### 4.1.2 推断依据

推荐使用以下特征联合推断：

- 字符框或文本行框的高度中位数
- 同一段内字符框高度的稳定性
- 同一风格文本块的聚类结果
- 基线位置
- 标题、正文、注释之间的层级关系

### 4.1.3 用“风格聚类”而不是逐块独立定字号

更稳的方式是先对文本块做风格聚类，例如：

- 正文
- 一级标题
- 二级标题
- 图表注释
- 页眉页脚
- 脚注

然后再给每一类一个 canonical 字号，例如：

- 正文：10.5pt
- 一级标题：16pt
- 二级标题：13pt
- 图注：9pt

这样可以避免单个块识别异常导致整篇文档字号混乱。

### 4.1.4 推断结果应吸附到常见字号网格

推断出来的字号最好吸附到常见字号值，例如：

- 9
- 9.5
- 10
- 10.5
- 11
- 12
- 14
- 16

不要保留太多奇怪的小数位。

---

## 4.2 行距推断

### 4.2.1 不要直接从文本框高度推行距

OCR 输出的是字符框、文本框，不是排版系统中的基线。

更合理的方式是：

- 先估计每一行的 baseline
- 再计算相邻文本行之间的 baseline distance

### 4.2.2 两种候选表达

对同一类文本块，建议同时计算：

- **绝对行距候选**：以 pt 为单位
- **相对行距候选**：`baseline_distance / font_size`

然后判断哪一种更稳定：

- 如果绝对值更稳定，可能更像固定行距
- 如果比例更稳定，可能更像 `1.25 / 1.5 / 1.75` 这类倍数行距

### 4.2.3 推荐策略

- 正文段落优先还原为 **multiple line spacing**
- 表格单元格、表单、票据字段更适合 **exact / at least**

原因是正文需要更自然地重排，而表格和票据更依赖几何稳定性。

---

## 4.3 页边距推断

### 4.3.1 不要拿最外层文字框直接当边距

最左边的文字不一定代表正文左边界，可能是：

- 短标题
- 列表项
- 首行缩进段
- 引用块
- 页眉
- 装饰元素

同理，最右边的字符也不一定代表正文右边界。

### 4.3.2 应先推断稳定的内容框（content frame）

推荐流程：

1. 剔除页眉、页脚、页码、装饰图、孤立短块
2. 只保留正文段落块
3. 统计跨页的稳定左边界和右边界
4. 使用 robust median 或分位数估计正文内容框
5. 再把首行缩进、引用缩进、列表缩进从内容框中剥离

最终得到：

- 页面物理尺寸
- 正文内容区宽度
- 左右页边距
- 段落缩进

这几者不应混为一体。

---

## 5. 怎样保证整页内容不溢出

## 5.1 先不要整体缩放，先检查容器尺寸是否正确

很多溢页其实不是字号本身错了，而是容器尺寸算错了。

在 Word 中，文本内容所在容器可能是：

- 正文页面区域
- 多栏中的某一栏
- 表格单元格
- 文本框
- 图文混排区域

因此在渲染前，必须先正确计算：

- 页面宽高
- section 边距
- 分栏宽度和 gutter
- 表格总宽度
- 单元格内边距
- 图片占位宽度

如果容器宽度计算错误，那么后面再怎么调整字号和行距也无济于事。

---

## 5.2 分级拟合策略

建议采用“从轻到重”的版面修正顺序。

### 第 0 级：先修容器

优先检查：

- 页面尺寸是否正确
- 页边距是否合理
- 表格宽度是否超过正文区
- 图片是否超出容器宽度
- 多栏布局的列宽和 gutter 是否正确

### 第 1 级：先改不影响视觉语义的属性

优先调整：

- 表格固定宽度
- 图片按容器宽度约束
- 修正段前段后过大的误判
- 为标题设置 `keep_with_next`
- 为长段落启用 `widow_control`
- 必要时启用 `keep_together`

这一层通常已经能修掉很多微小溢出。

### 第 2 级：只做局部微调

若仍有问题，再按顺序尝试：

1. 减小段前段后间距
2. 微调行距
3. 微调图片高度或表格高度
4. 最后再微调字号

推荐不要一开始就动字号，因为用户对字号最敏感，对段后 1pt、行距 -0.03 倍通常不敏感。

### 第 3 级：最后才整体缩放

只有在局部修正仍无法解决时，才允许启用整页缩放。

但即使启用了整体缩放，也应把它视为 **render-time transform**，而不是修改真实样式。

---

## 6. 推荐使用“两遍排版”机制

## 6.1 第一遍：忠实渲染

第一遍不做任何防溢出缩放，只按照 `style_inferred` 忠实生成 DOCX。

目标是收集问题：

- 哪些段落跨页异常
- 哪些表格超宽
- 哪些图片超高
- 哪些页面多出一页
- 哪些标题孤立在页尾

### 6.2 第二遍：约束求解式修正

第二遍只对有问题的区域做最小破坏修正。

可以给不同修正动作赋一个代价（cost），例如：

- 改段后间距：cost = 1
- 改段前间距：cost = 1
- 改行距：cost = 2
- 改图片缩放：cost = 3
- 改表格宽度：cost = 4
- 改字号：cost = 5
- 改页边距：cost = 8
- 整页统一缩放：cost = 10

系统优先选择 cost 最低且能消除溢出的修正组合。

这种方法比“一有问题就整页缩小”稳定得多。

---

## 7. IR 设计建议：为样式推断与版面拟合分层建模

建议在你的 IR 中显式区分：

- 页面级信息
- 容器级信息
- 推断样式
- 渲染修正
- 置信度

示例：

```json
{
  "page": {
    "source_size_px": [2480, 3508],
    "target_page_size_pt": [595.3, 841.9],
    "section_margin_pt": {
      "top": 72,
      "bottom": 72,
      "left": 90,
      "right": 90
    }
  },
  "block": {
    "role": "paragraph",
    "bbox_source": [120, 300, 2200, 560],
    "container_id": "body_col_1",
    "style_inferred": {
      "font_family": "SimSun",
      "font_size_pt": 10.5,
      "line_spacing_mode": "multiple",
      "line_spacing_value": 1.5,
      "space_before_pt": 0,
      "space_after_pt": 6,
      "first_line_indent_pt": 21
    },
    "style_confidence": {
      "font_size": 0.82,
      "line_spacing": 0.77,
      "margin": 0.93
    },
    "render_fit": {
      "font_size_delta_pt": 0,
      "line_spacing_delta": -0.03,
      "space_after_delta_pt": -1,
      "local_scale": 1.0
    }
  }
}
```

### 7.1 为什么要加 `style_confidence`

因为很多页面并不是所有样式都能高置信度推断。

例如：

- 页边距可能很稳定，置信度高
- 行距可能受 OCR 基线漂移影响，置信度低
- 字号可能对正文稳定，但对图注不稳定

有了 `style_confidence`，渲染器就可以做策略性决策：

- 置信度高的属性尽量不要改
- 置信度低的属性允许更大幅度的拟合修正

## 8. 表格、图片、标题的特殊处理建议

## 8.1 表格

表格是最常导致页面撑爆的对象。

建议：

- 不要让表格自动适应页面后再由 Word 随意改列宽
- 应先计算正文区可用宽度
- 表格总宽必须限制在正文区以内
- 列宽按比例归一
- 单元格内长文本优先换行，不要靠整表缩小来补救

## 8.2 图片

图片的原始 DPI 往往不可靠，因此不要直接依赖源图像 DPI 来决定插入尺寸。

应基于：

- 所在容器宽度
- 原始图像宽高比
- 页面高度余量

显式设置插图宽高。

## 8.3 标题与分页

标题后面如果只跟很少内容，或者标题单独落在页尾，很影响阅读体验。

此时优先使用分页控制，而不是缩字号。

建议：

- 标题使用 `keep_with_next`
- 长段使用 `widow_control`
- 必要时使用 `keep_together`

---

## 9. 推荐算法流程

### 9.1 样式推断阶段

1. 在源页面坐标系中做 block/line/span 识别
2. 估计页面物理尺寸和目标纸张尺寸
3. 根据字符框、行框、基线节距推断字号和行距
4. 对文本块做风格聚类，得到 canonical 样式
5. 推断正文内容框与页边距
6. 生成 `style_inferred`
7. 给每个属性计算 `style_confidence`

### 9.2 第一遍渲染阶段

1. 按 `style_inferred` 生成 DOCX
2. 按真实容器宽度渲染段落、表格、图片
3. 启用合理的分页控制规则
4. 记录所有溢出和分页异常

### 9.3 第二遍拟合阶段

1. 对有问题的页面建立候选修正集合
2. 按 cost 从低到高尝试修正
3. 优先修段间距、行距、局部对象尺寸
4. 必要时才调整字号
5. 最后才考虑整页缩放
6. 生成 `render_fit`

### 9.4 最终输出阶段

最终渲染值应为：

- `effective_style = style_inferred + render_fit`

但保存 IR 时：

- `style_inferred` 必须保持不变
- `render_fit` 单独记录

---

## 10. 最终建议

可以把整套原则总结为四句话：

### 10.1 不要把整体缩放后的值当作真实字号

缩放只是渲染修正，不是原文样式。

### 10.2 字号、行距、边距要在源页面坐标系中推断

不要从已经缩放后的 DOCX 结果反推。

### 10.3 不溢页要靠“两遍排版 + 分级修正”

先忠实渲染，再最小破坏修正，而不是一开始就整页缩小。

### 10.4 IR 必须把 `style_inferred` 和 `render_fit` 分开

这是保证“样式还原”和“版面拟合”都可持续演进的关键。

---

## 11. 实施优先级建议

如果你准备实际改造系统，推荐按以下顺序推进：

### 第一阶段

- 在 IR 中加入 `style_inferred`
- 在 IR 中加入 `render_fit`
- 在 IR 中加入 `style_confidence`
- 停止把缩放结果回写到原始样式字段

### 第二阶段

- 增加 style clustering
- 增加 baseline-based line spacing inference
- 增加 content frame / margin 推断

### 第三阶段

- 实现第一遍忠实渲染
- 实现第二遍局部拟合
- 为不同修正策略建立 cost 模型

### 第四阶段

- 对表格、图片、分页做单独的局部优化策略
- 引入按页型选择不同拟合策略
- 对正文页、表单页、试卷页、宣传页分别调参

---

## 12. 一句话结论

> 最稳的方案不是“统一缩小直到不溢页”，而是“先还原真实样式，再在渲染阶段做最小破坏拟合”，并且始终把 `style_inferred` 与 `render_fit` 分开保存。
